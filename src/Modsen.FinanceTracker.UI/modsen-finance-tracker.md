# Техническое задание: Консольное приложение "Modsen Finance Tracker"

## 1. Общее описание

Разработать консольную систему для учета личных доходов и расходов. Цель проекта — освоение принципов ООП, паттернов проектирования и работы с платформой .NET.


## 2. Основные сущности / понятия

### 2.1. Транзакция (`Transaction`)

Центральная сущность приложения. Является базовым классом или абстракцией.

* **Свойства:**
    * `Id` (Guid) — уникальный идентификатор записи.
    * `Amount` (Decimal) — сумма операции.
    * `DateTime` (DateTime) — дата и время совершения операции.
    * `Category` (Enum или Class) — категория
    * `Description` (String) — краткое описание или комментарий.


* **Типы:** Разделение на `IncomeTransaction` (Доход) и `ExpenseTransaction` (Расход) для реализации паттерна Factory.

### 2.2. Кошелек / Счет (`Wallet`)

Класс, отвечающий за агрегацию транзакций и расчет состояния баланса.

* **Ответственность:**
    * Хранение списка транзакций.
    * Вычисление текущего остатка.
    * Валидация возможности совершения расхода (проверка на «уход в минус»).



### 2.3. Категория (`Category`)

Сущность для классификации транзакций.

* **Свойства:**
    * `Name` — название категории.
    * `Type` — тип (расходная или доходная).
    * `BudgetLimit` — (опционально) лимит по данной категории на месяц.



### 2.4. Конфигурация приложения (`AppConfiguration`)

Объект для хранения глобальных настроек.

* **Параметры:**
    * `Currency` — используемая валюта (символ или код).
    * `DataFilePath` — путь к файлу сохранения JSON.
    * `DateFormat` — формат отображения дат в консоли.


## 3. Функциональные требования

### 3.1. Управление транзакциями

* **Создание:** Добавление записи (сумма, категория, дата, комментарий).
* **Чтение:** Просмотр списка всех транзакций с возможностью пагинации (по 10 записей).
* **Обновление:** Редактирование любой части существующей транзакции по её ID.
* **Удаление:** Удаление записи по ID с подтверждением.

### 3.2. Аналитика и фильтрация

* Вывод общего баланса (Доходы - Расходы).
* Фильтрация списка по диапазону дат (например, за текущий месяц).
* Группировка расходов по категориям с вычислением процентного соотношения.

### 3.3. Сохранение данных

* Автоматическое сохранение данных при выходе и загрузка при старте.
* Использование формата **JSON** для хранения файлов.

### 3.4. Система отчетов (Экспорт)

* Возможность выгрузки отчета в разные форматы:
    * Текстовый файл (.txt) — упрощенная таблица.
    * CSV файл — для открытия в Excel.

## 4. Нефункциональные требования

### 4.1. Архитектурные принципы

* **SOLID:** Соблюдение принципа единственной ответственности (Single Responsibility) и инверсии зависимостей (Dependency Inversion).
* **Устойчивость:** Приложение не должно падать при вводе букв вместо цифр или при отсутствии файла базы данных.

### 4.2. Паттерны проектирования

* **Repository:** Для абстракции логики хранения данных.
* **Factory Method:** Для создания объектов разных типов транзакций (например, `Income` и `Expense`).
* **Strategy:** Для реализации различных алгоритмов экспорта отчетов.
* **Singleton:** Для управления настройками приложения (пути к файлам, текущая валюта).

### 4.3. Тестирование

- Unit и интеграционные тесты
- Минимум 60% покрытия для бизнес-логики ключевых сервисов

### 4.4. Технологический стек

* Язык: C# (версия 10+).
* Платформа: .NET 8/10 Console Application.
* Система контроля версий: Git
